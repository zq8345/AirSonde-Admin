## R1 — 全站没有任何登出入口（Joe 点名，确认属实）

**实测证据（两路独立扫描，都是零命中）：**

| 扫描面 | 关键词 | 命中 |
|---|---|---|
| 运行中的 DOM（全元素文本节点） | 登出 / 退出 / 注销 / 切换账号 / logout / log out / sign out | **0** |
| 运行中的 DOM（全元素全属性） | 同上 + `cdn-cgi/access` | **0** |
| 源码 `public/` `src/` `scripts/` | 同上 | **0** |

（`README.md:341` 有一处「退出」，指的是脚本 exit，无关。）

**该放哪 —— 位置是现成的。** 侧栏底部 `#who.nav-foot` 已经在显示身份与版本：

```
dev-bypass · zq8345/AirSonde-Web
c164678（脏） · 67be86ee · FRA
```

实测几何：身份行 `58x13 @ (18,662)`，版本行 `171x16 @ (18,694)`。**「当前是谁」已经在那儿了，缺的只是它旁边的那个动作。**

**正确做法**：链接到 `/cdn-cgi/access/logout`。身份归 Cloudflare Access 管，后台没有自己的会话可清，任何自建的「清 cookie」都不会真的登出。

**不做的后果 —— 有一条比"共用设备换不了人"更硬：**

`设置` 页自己写着，Access 策略名单与 `ALLOWED_EMAILS` 的**唯一对账办法**是：

> 「Cloudflare Access 那道门的策略名单本后台看不到……对账办法：让人真去登一次 —— 过不了 Access = 停在登录页；过了 Access 但不在下面这份名单里 = 403。」

而 `_whoami` 也重复了同一句。**没有登出按钮，这条自己写下来的对账程序就没法在同一台机器上执行** —— 你无法在登入状态下换一个账号试。而两张名单必须集合相等，正是项目规则 §1 里写明「wanew 同一个病犯过三次、AirSonde 第一天就犯过一次」的那一条。

再加上常规后果：共用设备上换不了人；离开工位时没有办法主动结束会话。

## Y1 — 同一个二值状态，界面上并存四套说法

**判据**：AU2「同一概念是否同一个词」。以下全部是**渲染出来的字**，不是源码。

| 位置 | 元素 | 显示的词 |
|---|---|---|
| 产品列表 · 筛选 tab | `button.stab` | 全部 / **在线** / **未上架** |
| 产品列表 · 行内徽章 | `span.badge.badge-published` | **在线** |
| 产品列表 · 行内动作 | `button.linkish` | **下架** |
| 批量条 | `button` | **批量上架** / **批量下架** |

| 产品预览 · 内部信息 | 表格行 | 状态 **在线** |

两套隐喻混用：「在线 / 离线」与「上架 / 下架 / 未上架」。用户看到徽章写「在线」，要去点一个叫「下架」的按钮，才能让它变成「未上架」。

**建议改法**：选一套隐喻贯穿到底；编辑器下拉按同一套显示中文，`value` 保持英文不动。

## 更正一 — 撤回 ⚪ W2「`#preview` 是空的遗留 DOM 节点」

### 我当时写了什么

> ## W2 — `#preview` 是空的遗留 DOM 节点
> `detailView` 下有 5 个直接子元素，其中 `DIV#preview` 高度 0、`innerHTML` 为空字符串。预览实际渲染在 `#viewPane`（1013px）。两个名字都叫 preview 的容器，只有一个在用。

### 事实是什么（我自己复验过，不是转述）

`#preview` 是**活的**，它承载保存前的 diff / 确认界面。在**我当时实际审计的那份字节**（快照 `app.js` sha256 `1fd3f912…`）里：

| 行 | 代码 | 作用 |
|---|---|---|
| `1058` | `const box = $("#preview"); box.hidden = false; box.innerHTML = "";` | **写入路径** —— 取消隐藏后往里建 diff 界面 |
| `1192` | `$("#preview").prepend(mkNotice("bad", "提交请求失败：" + e.message))` | 往里写失败提示 |
| `431` | `const pv = $("#preview"); pv.innerHTML = ""; pv.hidden = true;` | `clearProductPanes()` —— 离开产品时**清空并隐藏** |

当前 HEAD `2eb49ad` 同样成立（写入路径在 `app.js:1111`）。

**⇒ 我观测到它"空且 0 高"，正是因为它当时处于隐藏态 —— 而 `clearProductPanes()` 的职责就是让它在隐藏时保持为空。我把一道正常工作的闸的产物，读成了"这东西没人用"。**

更讽刺的是：`app.js:423` 就有一条注释记着反向的旧事故 ——「`#preview` 残留 1036 字符（虽然 hidden，但内容还在：谁一 un-hide 就露出上一个产品的 diff）」。**我看到的那个"空"，正是那次事故的修复成果。**

**代价**：Admin 窗差一点据此删掉一个在用的节点。

### 判据错在哪（这条比结论本身重要）

**「空」不等于「死」。** 判一个 DOM 节点是不是死代码，不能只看某一时刻它有没有内容 —— 隐藏态的容器本来就该是空的。**正确判据是：有没有代码往它写。** 一次 `grep -n 'preview' app.js` 就能推翻我的结论，而我没做——因为我把它归进了"⚪ 建议"，而对 ⚪ 我放松了取证标准。

**这与本报告「我自己查错又撤回的」第 4 条（`input[type=text]` 匹配不到没写 `type` 属性的输入框）是同一族错误：判据只认得一种形态，就只查得出那一种。** 区别只在于那一条我在交付前自己抓住了，这一条没有。

**给后续审计的一条硬规矩**：
- 断言"某个东西是死的 / 没在用" ⇒ **必须给出"没有任何写入方"的证据**，而不是"我看它是空的"
- ⚪ 级别的条目**不降低取证标准** —— 本次代价证明，⚪ 一样会被人照着动手
